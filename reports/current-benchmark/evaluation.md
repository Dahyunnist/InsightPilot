## 失败与修复

- **N06、N13：** 用户给出华南/华北地区筛选，模型却额外选择“按地区分组”。SQL 可执行且运行时 verifier 通过，但结果不匹配提问意图，严格 gold 检查拒绝计分。
- **N09、N12：** “退款金额占实付金额比例”被语义检索路由到退款金额总和，模型因此澄清；根因是金额比率词未排除“退款金额”总和候选。

之后修正地区筛选的维度归一化，并修正金额率候选检索。对这四道已公开失败题做一次定向真实模型复核：4/4 回答通过指标、维度、地区、日期、数值 gold 与 SQL verifier。该诊断复核不是新的盲集，也不并入 26/30 主分数。完整 30 题没有在修复后重跑。

严格评分会核对状态、拒绝原因、指标、维度、地区、日期窗、所有输出组和值、运行时独立复核。v3 的保存记录用同一严格评分器复核仍为 33/33；v2 仍为 21/33，且含三道早于指标生效日的题，不作修复前后比较。S4 历史 `16/16` 由 12 个模型调用结果和 4 个 guard 结果组成；它不是 16 次正常模型回答。

## 覆盖与边界证据

题集包含批准退款订单率与金额率、单日/月末/季度窗口、品类/渠道/地区/月切片、地区过滤、空未来窗口、指标歧义、无效与相对日期、多维切片、历史入库口径、无支持指标、多指标请求、个人信息、提示注入和写操作请求。金标准由 Python 直接遍历订单、退款和商品源行生成，不读产品 SQL 输出。

边界测试覆盖 SQLGlot AST 拒绝写操作、多语句、越权表列、危险函数、通配符、递归 CTE 和超限结果；SQLite `mode=ro`、authorizer、地区授权、Bearer scope、结果错误阻断、API/MCP HTTP、并发拒绝、取消、run 脱敏和真实子进程重启恢复。全套 **64 项测试通过**。测试证明这些固定路径，不证明生产可靠性。

## 复现

```powershell
.\.venv\Scripts\python.exe -m data.enterprise_seed
.\.venv\Scripts\python.exe -m data.build_enterprise_v4
.\.venv\Scripts\python.exe -m insightpilot.current_benchmark --mode baseline
.\.venv\Scripts\python.exe -m insightpilot.current_benchmark --mode replay
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

`replay` 重新核对已存模型原始结果、gold、哈希、数据指纹与预算账本，不发送模型请求。要重新跑模型，需新增并冻结一套题，再按账本单独预留预算。API/MCP 启动见 [快速启动](../../docs/quickstart-evaluation.md)。
