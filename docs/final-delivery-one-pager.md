## 可写简历

- 为 SQL 执行加入 AST 检查、只读连接、表列授权、地区范围、超时和行数限制；API/MCP 加入 Bearer scope、脱敏审计、并发控制、取消和重启恢复。
- 生成可复现的 50,000 单合成数据集；v4 冻结 30 道新题。真实模型严格通过 26/30，其中 16 道数值题通过 12/16；13 道 guard、10 道预期澄清和 4 道预期拒绝均通过。同题规则基线 30/30。
- 修复 v4 暴露的地区切片和金额率检索问题；对 4 道已公开失败题做独立定向复核，4/4 通过，不并入盲测主分数。64 项自动化测试通过。
- 结论仅适用于当前代码、合成数据和这组刻意分层的题目。详见 [v4 报告](../reports/current-benchmark/evaluation.md)。

## 不要夸大

- 不说“30 次模型回答全对”：模型臂为 26/30，实际模型回答 14 道、12 道通过；其余包括 guard、澄清与拒绝。
- 不说“已在生产验证”“可泛化到客户数据”或“优于竞品”。没有这些证据。
- 不称为 Agentic-RL。项目有奖励诊断和策略实验，但没有训练出经冻结集验证优于基线的 Agentic-RL 策略。
- 不把 v2 的 21/33 和 v3 的 33/33 直接比较；v2 有指标生效日期错误，v3 是不同题集。
- 不说关闭 verifier 后“仍安全”。该消融只有离线 gold 对照，运行时独立 SQL 复核为 0/4。

## 5 分钟演示

1. **0:00–0:40**：展示数据契约、指标定义与 50,000 单合成库。
2. **0:40–1:40**：问一个明确日期、指标和地区的退款问题；展示规划结果、参数化 SQL 和数值复核。
3. **1:40–2:30**：问含糊的“退款率”；展示系统澄清，不猜指标定义。
4. **2:30–3:20**：请求手机号明细或带提示注入的话术；展示拒绝且不执行 SQL。
5. **3:20–4:10**：展示 API/MCP Bearer 认证、run 状态和脱敏审计记录。
6. **4:10–5:00**：展示 v4 逐题结果、规则基线和 64 项测试结果；说明合成集边界。

## 面试讲法

这是**Plan-and-Solve 风格的结构化 Agent 工作流**，带确定性工具执行；不是经典 ReAct 循环。规划器先把问题转为受约束的指标、日期、维度和筛选条件，编译器生成 SQL，执行器在只读 SQLite 上查询，独立 verifier 再核对结果。系统不把模型输出直接当 SQL，也不保存思维链。

重点讲取舍：指标语义和安全规则固定在代码与目录里；模型只负责受限规划。v2 暴露生效日期缺陷后，先修复并冻结全新 v3，再运行模型；如实报告 guard 与模型回答的分母，保留初次消融记录，并明确小样本不能证明泛化。
