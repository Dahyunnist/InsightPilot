# S15 学习记录：v4 基准、口径审计与模型复核

## 本阶段目标

从业务分析者视角核对题目、指标语义、日期、切片、澄清、拒绝、SQL、权限、解释输出、API/MCP 和错误恢复；统一一份有独立 gold、可复现的当前基准，并按 USD 4.00 上限控制新模型调用。

## 先厘清历史数字

- S4 的 16/16 来自 16 个案例：12 个普通数值问题实际调用模型，另 2 个澄清和 2 个拒绝由确定性 guard 处理。
- v3 的 33/33 是 11 道题各运行 3 次；7 道 guard 题贡献 21 个结果，4 道数值题贡献 12 次模型回答。
- v2 的 21/33 是另一套题，含三道早于指标生效日的用例。与 v3 不做纵向增益比较。
- 原 verifier 评测器会把错误维度/过滤范围计为通过，也不比对拒绝原因；严格评分已补全状态、原因、指标、维度、范围、日期、数值及 verifier 检查。
- 题集哈希原按平台文件字节计算，Windows 与 Unix 换行会产生不同结果；现统一按 LF 规范化。v3 活动归因 gold 还受 Python set 遍历顺序影响末位小数；按订单 ID 排序，并用两个 `PYTHONHASHSEED` 做稳定性测试。
- 规划器原始请求日志漏计 JSON 无效后的重试；现逐次记录真实 HTTP 请求、usage、时延和服务返回模型名。

## v4 冻结集与结果

模型运行前提交 `22e3c27` 冻结 30 个新问题、gold 和 manifest。16 题需数值回答；13 题预期由确定性 guard 澄清或拒绝；另 1 题预期模型澄清。覆盖两种退款率口径、日期边界、品类/渠道/地区/月切片、地区过滤、空未来窗、歧义、权限拒绝、注入和写请求。Python 源行 oracle 独立于生成 SQL 与模型答案；精确题文本无重合，语义相似无法排除。

同题固定规则基线 30/30，包含 16 个经 SQL 和 verifier 核对的数值回答。真实模型主臂严格通过 26/30：16 道预期数值题中 12 道通过，13/13 guard、10/10 预期澄清、4/4 预期拒绝通过。模型调用 17 个案例，共 18 次 HTTP 请求；首题有一次结构化 JSON 重试。不要把 26/30 或 33/33 表述成模型准确率。

失败给出两个可定位问题：地区过滤被多加成地区分组；“金额占实付金额比例”被检索到退款金额总和，导致不必要澄清。修复规划维度归一化和金额率检索后，对这四道已暴露题做一次定向真实模型 smoke，4/4 按独立 gold 和 SQL verifier 通过。它是修复诊断，不并入盲测主分数；v4 未在修复后全量重跑。

## 安全、运行和成本证据

64 项测试通过，覆盖 AST/authorizer/只读库、越权地区和 scope、结果不匹配拦截、API/MCP transport、并发/取消、脱敏和进程重启恢复。v4 题集包含 30 个案例，但只测两种率指标；不代表全部目录指标或真实业务覆盖。

未找到旧成本账本。检查原始 JSONL 有 token 回执的历史共 76 次请求、79,464 tokens；按峰时、全部缓存未命中估算 USD 0.065552，额外预留使历史账面 USD 0.10。v4 主臂 list-price 估算 USD 0.01397944，四题复核 USD 0.00291461；共计 USD 0.01689405。按保守账面预留计，USD 4 上限仍余 USD 3.8597664。完整明细见 [成本账本](../../reports/model-experiment-cost-ledger.json)。
