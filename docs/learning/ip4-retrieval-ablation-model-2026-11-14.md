# IP-4 检索开关模型对照：预检与恢复说明

## 本阶段结果

已按用户批准范围准备 22 道冻结合成题，比较“指标检索开启”和“指标检索关闭”。离线预检通过。实际运行在供应商余额查询处停止，查询返回 `URLError`；因此无法确认当前余额。没有发送题目、gold、数据库行、SQL 或查询结果；模型请求数为 0，账本未扣款。此前余额快照不能代替本次实时检查。

冻结题集、数据身份和 gold 哈希均已核验。当前工作库与冻结数据库哈希不同，因此运行器会在操作系统临时目录按冻结种子重建数据库；重建哈希和指纹必须精确匹配 manifest，否则立即停止。仓库内数据库不会被覆盖。

## 评测边界

- 题集：22 道退款与营销 ROI 合成题。
- 两臂：同一题集分别使用检索候选和完整允许指标 ID；本地规则在请求前拦截 3 道题。
- 冻结计划最多 68 次请求；每次输入内容最多 4,000 UTF-8 字节、输出最多 960 token，保守费用预留 `$0.159936`，不超过已授权的 `$0.1873344`。
- 每个模型 user payload 仅包含 `question`、静态 `candidate_metrics`、`allowed_metric_ids`。`case_id`、gold、期望答案、数据库行、SQL 和查询结果不会发送。
- gold 只在本地独立评分；合成样本结果只描述本题集，不外推到生产或总体准确率。

## 运行与恢复

使用项目虚拟环境运行：

```powershell
.\.venv\Scripts\python.exe .\scripts\run_ip4_retrieval_ablation_model.py --preflight-only
.\.venv\Scripts\python.exe .\scripts\run_ip4_retrieval_ablation_model.py
```

第一条只做冻结哈希、数据库重建、prompt 大小、请求上限和预算检查。第二条先查询供应商账户余额；余额满足全额预留后，才会先扣留预算再调用模型。余额检查同时支持 USD 余额和按 7.5 CNY/USD 折算的 CNY 余额。若查询失败或余额不足，不会发模型请求，也不会减少账本余额。若运行中断，完整预留留在账本中，需核实调用账单后再释放。

## 面试讲解

这组实验用于隔离检索对指标选择和最终查询正确率的影响。两臂共用相同问题、模型、温度、输出约束和本地执行/验证链路，只改变指标候选上下文。模型只生成受限 JSON 查询计划，SQL 编译、只读策略、数据库执行和独立复核仍由程序完成。当前没有模型结果，不能声称检索提升了准确率。
