# S4 学习记录：黄金集评测与结果复盘

## 阶段目标

把固定口径变成可重复的端到端回归，并保留逐题证据。评测必须真实调用 `.env` 配置的模型；无法从服务响应取得 token 用量时记为缺失，不推算。

## 数据与状态流

`evals/cases.jsonl` → `insightpilot.evaluate` → 每题调用 `InsightPilot` → 计划校验、模板 SQL、只读执行、独立复核 → 按 case 的预期值和容差比较 → 原始 JSONL 与汇总 JSON/Markdown。

正常案例检查最终状态、指标 ID、每组精确金额/订单数及比率；歧义案例检查 `clarify`，拒绝案例检查状态与拒绝原因。SQL 成功率另要求回答态和独立复核都通过。数值比较使用 case 指定的绝对容差。

关键文件：

- `evals/cases.jsonl`：12 个正常、2 个澄清、2 个拒绝用例。
- `insightpilot/evaluate.py`：黄金集执行、数值比较、遥测统计和六题检索消融。
- `insightpilot/planner.py`：记录模型返回的 usage 与模型调用耗时；对非法 JSON 重试一次。
- `reports/evaluation-raw.jsonl`：逐题原始结果，保留计划、SQL、行和复核证据。
- `reports/retrieval-ablation-raw.jsonl`：六题关闭检索时的真实结果。
- `reports/evaluation-summary.json`、`reports/evaluation.md`：机器可读和人工可读汇总。

## 设计取舍

- 日期从问题里的明确日历日期确定，结束日转换成半开区间；模型只抽取指标、地区和维度。这样固定日期口径，避免模型改写区间边界。
- 主评测逐条调用当前配置模型；每次记录 run、耗时和可用 token 用量。原始文件保留失败项和 SQL，便于复盘。
- invalid structured response 重试一次。首轮 N08 曾遇到 JSON 截断，加入重试后整组通过；重试增加极端情况下的调用成本和延迟。
- 消融只取六道代表题，关闭检索并允许模型看完整指标 ID 列表。它用于观察候选检索的作用，不是统计显著性实验。
- 数据集修正：按固定数据重新核对 N08 第二周期为 9/9；N10 退款事件窗口金额为批准 30,000、待处理 10,000、拒绝 5,000 分；N11 移到无订单日以检验空分母；N12 cohort 为 80,000 分、9/9 单。这些修正写进 gold，而非迁就模型输出。

## 两条失败路径

1. 模型响应被截断或不是合法 JSON → `PlanError` → 自动重试一次；再次失败则返回 planning failed。原始记录保留失败状态，不伪造结果。
2. 模型选出不兼容指标/维度，或独立复核不一致 → 编译失败或 verification failed → Agent 不生成业务结论。消融样本 N07 显示关闭检索后可能选择不兼容维度；主检索流程通过该题。

评测日期：2026-10-19。固定合成数据库、当前 `.env` 模型配置。

- 全部 16/16：正常 12/12、澄清 2/2、拒绝 2/2。

## 亲手实验（约 15 分钟）

1. 查看 `evals/cases.jsonl` 中 N01、N08、N11，说明时间边界、双周期和空分母的期望值（4 分钟）。
2. 运行评测命令，查看 summary 与失败列表（5 分钟）。每次真实评测会调用模型，按 `.env` 供应商计费。
3. 对比主评测和 `retrieval-ablation-raw.jsonl` 中 N07、N12 的模型计划（4 分钟）。
4. 修改一个问题措辞但不改 gold，重跑单例需扩展 runner；记录指标选择或澄清失败，而非修改期望值迎合输出（2 分钟）。

检查点：能解释 numeric pass 与 SQL executable 的差别，并说明为何 16 题不能代表生产泛化。

## 面试追问与回答

**问：如何防止评测被模型自己的答案带偏？**

答：黄金值由固定 SQLite 数据和业务契约独立计算。比较器按 case 读取预先版本控制的期望值；模型不能写入 gold。

**问：为什么保留原始 SQL 和行？**

答：仅有通过率无法定位口径、计划、执行或复核错误。逐题原始记录可审计实际计划与结果；文件只含合成数据，仍应避免把包含过滤条件的原始输出上传。

**问：16/16 是否说明模型可上线？**

答：不能。样本仅 16 条，来自单一固定合成库和一次配置；还缺真实业务样本、并发与故障测试、权限审计和 SLA 验证。
