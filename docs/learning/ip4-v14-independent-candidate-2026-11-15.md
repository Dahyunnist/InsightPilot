# IP-4 v14 独立题集候选

## 本阶段解决的问题

旧 IP-4 运行的请求投递状态不明，不能把旧题继续称为盲测。本阶段构造独立题目与独立合成数据库，供所有者审题后决定是否做真实模型评测。当前只完成候选集，不代表评测已运行。

## 数据与状态流

固定随机种子生成 50,000 条合成订单和多域 SQLite 数据库。生成器构造退款与营销 ROI 两类问题，每类 7 道可答题、4 道澄清或拒答题。候选题、gold、数据库和 manifest 写到仓库外的新目录。代码检查候选题与旧 v13 题文本无重复。

可答题的退款 gold 由源行 oracle 计算，并与编译后的只读 SQL 结果核对。营销 ROI gold 由两套独立 Python oracle 计算，再与只读 SQL 结果核对。任一核对失败，构建即失败，不生成可发布候选。

只有题目及静态候选指标会进入潜在模型请求。Gold、SQL、查询结果、数据库行和私有数据均排除。模型调用前必须由所有者审阅题目，并完成余额预检。

## 关键设计与取舍

- 新题使用新业务措辞和随机退款日期，不从旧题复制后改日期。
- 日期区间在 gold 中采用右开区间；用户问题显示含首尾的自然日期。测试检查两者边界一致。
- 输出目录必须在仓库外且不存在，避免覆盖旧候选、评测报告或用户文件。
- 首先做离线候选构建，不把预算门禁或 scripted oracle 结果冒充真实模型成绩。

## 失败路径

1. SQL 与 Python oracle 不一致：构建抛错，不产出候选。排查指标口径、日期边界和分组语义后再重跑。
2. 输出目录已存在或落入仓库：构建拒绝写入。换一个新的仓库外目录，保留原目录供审查。
3. 日期区间问法与 gold 不一致：单测失败，修正题面后重新生成并核对新 hash。

## 面试追问

**为什么不直接复用旧测试集？** 旧集合已有请求尝试，且部分请求无响应；独立题目可减少已见题偏差。文本去重只能证明没有完全重复，不能证明统计意义上的独立性。

**如何降低 gold 自证风险？** 退款用源行 oracle 对照 SQL；营销用独立 Python 事件 oracle 和账本 oracle 对照 SQL。它们共享业务定义，仍需人工抽查口径。

**为何不把 gold 发给模型？** 模型只负责计划生成；gold 用于本地评分。发送 gold 会泄漏答案并破坏评测有效性。
