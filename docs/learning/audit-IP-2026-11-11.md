## 决策

IP-2 已有完整第二业务域与语义闭环，不重复加指标。4 题 v2 仅足以作烟雾测试；新建并冻结 24 题 v3，覆盖退款与营销 ROI 各 12 题，其中 16 可答、8 为 guard。Gold 值取自只读编译 SQL，并与独立 Python oracle 逐题核对；营销另有第二 Python oracle。blind/gold 精确重叠为 0；数据仍为同一固定合成 seed，不是新抽样数据集。RulePlanner 基线 19/24，可答 11/16，拒绝 4/4；5 个失败留在基线报告中。未调用模型。容器 Python 3.12.15、网络关闭、dummy LLM 环境下，完整测试 117/117 通过；挂载盘触发的两项 SQLite 超时在 tmpfs 下通过。详见阶段记录、`reports/ip4-v3-verification.json` 和 `reports/ip4-v3-rule-baseline.json`。

IP-1/2/4 PostgreSQL 已验过的 RLS 与连接池恢复不重跑。IP-3 单次 Compose 结果只作容器功能证据，不外推生产负载或能力。宿主 Windows Python 3.14 的 asyncio 初始化曾阻塞；后续使用既有 Python 3.12 镜像和 tmpfs 完成全套测试。禁网且未传 `.env`，只用本轮 dummy 环境变量；没有真实模型或外部 API 调用。

IP-3 新增 SQLite 断连 API 回归 2/2 通过，覆盖失败运行状态、零自动重试、幂等重放/冲突、恢复后新键成功及取消持久化。PostgreSQL 16 tmpfs fixture 中强制终止池连接后，池重连且后续只读查询成功，细节见 `reports/ip3-postgres-disconnect.json`。该 PG 检查没有停掉 PostgreSQL 服务，也没有覆盖 PG 故障期间 API 的运行状态；IP-3 继续标为部分完成。

IP-3 随后完成 PostgreSQL 服务级故障验收：服务停止时 API 存活，分析在数据阶段以 `database_execution` 失败并持久化；同键幂等重放不重复规划；同一 DB 容器恢复后，新分析成功。连接错误触发自有 psycopg 池受控废弃，下一请求新建池；业务查询不自动重试。详细证据见 `reports/ip3-postgres-service-outage.json` 与阶段学习记录。模型中断和 OpenTelemetry 仍缺，因此阶段仍为部分。
