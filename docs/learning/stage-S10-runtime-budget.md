# S10：运行时模型预算与阶段轨迹

## 本阶段目标

限制单次分析的模型请求和输入规模，并让最终结果明确记录每个程序阶段的结果。

## 实现

- 单次分析最多两次模型调用，覆盖一次结构化规划与一次格式修复。
- 每次模型输入最多 12,000 字符；每次输出 token 配置硬封顶 1,200。
- 预算超限在发出请求前返回规划错误。
- 轨迹包含 preflight、planning、dataset、compilation、query、verification、answer 七阶段；最终结果写入 RunStore 时一并持久化。

## 边界

这提供最终结果级的阶段审计，不是进程崩溃后的中途续跑检查点。数据查询仍由程序编译、只读执行并独立复核。

## 验收

轨迹测试校验七阶段及顺序；现有模型客户端测试覆盖规划与响应解析。
