## X01 / X12 失败复审

离线复核保存的真实模型响应，不重发请求。X01 题目明确要求“批准退款的付款订单占比”，但 `retrieve_metrics` 把通用“占比”优先当成金额贡献度，候选只剩 `approved_refund_amount_contribution`。这是检索排序缺陷，不是 gold 歧义。修正规则：带“订单占比/订单比例/订单率/订单数”时不因通用“占比”加金额贡献分；X01 精确题面现命中 `approved_refund_order_rate`。新增 X01 规划回归及金额份额正例，均不调用模型。

X12 问“批准退款金额与实收金额的比值”。保存的原响应是 `clarify`；trajectory 显示 planning `blocked`，其余阶段 `not_reached`，没有 SQL 或查询执行。响应称候选里只有 `approved_refund_amount`，缺少“实收金额”定义。用原题面调用当前 `retrieve_metrics` 可复现同一缺陷：只返回 `approved_refund_amount`，不是模型随机拒答。原因是“批准退款金额”给金额总额加分，“比值”未触发比例指标，导致 `approved_refund_amount_rate` 落选。

修复检索规则：把“比值”识别为金额率，并在比值语境下不选单独的批准退款金额指标。新增 X12 原题面规划回归，验证命中 `approved_refund_amount_rate` 且日期窗为 2028-01-01 至 2028-01-08。X01、X12 的真实报告仍保留 18/20 原分数；离线规划回归不证明模型盲测已改善。端到端效果需新冻结集复测，先更新预登记并重新核验预算与供应商余额。
