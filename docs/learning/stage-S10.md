# S10 学习记录：扩大且隔离的冻结集

## 冻结边界

旧 B01–B03 已进入先前评测和 S9 策略选择，不能再算新 holdout。新增 `enterprise-blind-v2`，含 11 个未运行过模型的新 case；旧 v1 和旧报告保留为历史证据。

构建器按固定企业数据库的原始订单、退款、归因行用 Python 重算 gold。它与 SQL 模板、运行时 verifier 分开实现。B04–B06、B09、B13–B14 的澄清/拒绝标签由固定 guard 语义确定；B07 是确认无批准退款的真实分组零分母，B08 是空日期窗，B10 插入指令注入，B11 使用退款发生时间并覆盖晚到记录，B12 限定地区做多触点贡献。

`enterprise-holdout-manifest-v2.json` 锁定题数、数据 fingerprint、问题与 gold 哈希。构建时检查 S4 开发题和过去企业模型请求的完全相同问题，不改写 v1 gold。检查只证明精确文本无重复，不证明语义无重叠；数据与问题仍是合成设计。

## 安全边界修正

消融仅关闭独立复核，不关闭预检拒绝。此前 no-verifier 辅助路径会直接调用 planner；现在它先走同一只读/PII 预检，再进行计划、模板编译和只读执行。B09 不会把个人信息请求发送给模型或数据库。

## 验证

测试重建 50,000 单数据库和 v2 gold，核对 manifest、精确题泄漏、确定性澄清 guard，并让固定计划穿过真实只读 SQL 与独立 verifier，覆盖 B07、B08、B10–B12。

## 边界

v2 仍是 11 道精心分层的合成问题，不能代表客户总体。重复真实模型运行与系统故障验证分别留在 S11、S12 证据中。
