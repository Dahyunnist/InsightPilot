# S11 学习记录：重复真实模型评测

## 结果

v2 每题运行三轮，保留 33 条主臂原始记录；模型 `deepseek-v4-flash` 实际发起 15 次调用。原 gold 计分 21/33，三轮都通过相同 7 题。按题聚类 bootstrap 95% 区间 36.4%–90.9%，只描述这组刻意分层的合成题，不能推断客户总体。检索与 no-verifier 消融各跑一次，均为 7/11。Token、延迟和完整逐题差异见 [v2 评测报告](../../reports/enterprise-v2/evaluation.md)。

## 发现

- 三题时间窗早于指标生效日，原 gold 要求回答与语义目录冲突。原始 gold 和 21/33 不改；这些题排除出有效业务表现解读。
- 退款发生日问题三轮都选订单 cohort 金额指标；该 SQL 的 verifier 通过，但指标语义错。这证明 verifier 只验证选定公式的数字。
- “华东地区”作为字面过滤值导致空结果，空 control 也通过。规划器需从用户请求抽取、规范化已知地区；verifier 不可把不可信空结果当成无数据证明。
- 注入问题三轮都使结构化规划失败。虽未执行 SQL，安全拒绝分类不稳定。

这些是已知 v2 缺陷。v2 原始题和报告此后不用于调参 holdout；S12 修复会用新增确定性测试验证。新冻结题应独立编号并在运行前锁定。
